← 목록으로 돌아가기

구글 봇 크롤링은 네가 생각하는 것보다 훨씬 덜 해준다 — 을지로에서 진료하는 스파이더 로그 분석가의 사설

380,000개 URL을 가진 쇼핑몰이 실제로 구글에 색인된 페이지는 54,720개. 전체의 14.4%. 서버에 올려진 모든 페이지가 구글bot의 색인 대상이라는 착각에서 출발하는 순간, 크롤링 예산은 이미 새고 있다.

구조적으로 생각해라. 구글bot은 네 사이트 전체를 하루에 다 긁어가지 않는다. 서버 로그에서 확인 가능한 사실이다. 도메인 권한과 콘텐츠 신뢰도에 따라 배정되는 '시간 쿼터' 안에서 선택적으로 크롤링한다. 이 배정량이 바로 크롤링 예산이고, 이걸 진단하는 과정은 일정한 분기 구조를 따른다.

1단계: 크롤링 예산이 정말 소진됐는지부터 확인

서버 로그를 열어라. access.log에서 Googlebot의 User-Agent 필터링 결과를 보면, 하루 크롤링 요청 수를 확인할 수 있다. 요청 수가 1,000 미만이면 권한 문제고, 5,000 이상인데도 색인이 안 되면 다른 병목이다.

robots.txt가 핵심 분기점이다. Disallow 규칙이 비정상적으로 넓으면 크롤링 자체를 막고 있는 거고, sitemap.xml 경로가 기재되지 않았으면 구글bot은 색인 후보 목록을 아예 받지 못한다. robots.txt를 열어Disallow 라인에 와일드카드(*)가 과도하게 걸려 있거나, sitemap.xml 경로가 누락되어 있다면 크롤링 예산분배 자체가 비정상이다.

2단계: 구글bot이 실제로 어디를 기어다니는지 추적

서버 로그에서 크롤링 경로를 시각화해보면 충격적인 장면이 나온다. 카테고리 필터 URL, 세션 파라미터, 무한 스크롤 페이지, 정렬 옵션 조합. 수만 개의 URL이 사실상 동일한 콘텐츠를 가리키고 있다.

최다 범인은 오프닝 페이지다. 내부 링크로 연결되지 않은 페이지를 말한다. 링크 깊이가 3단계 이상 떨어진 페이지는 색인에서 사실상 제외된다. 색인에 넣고 싶으면 sitemap.xml에 명시적으로 포함하거나, 최소한 메인 페이지에서 2클릭 이내로 접근 가능하게 만들어야 한다. 아닐 경우 해당 페이지는 구글bot에게 존재하지 않는 거나 마찬가지다.

3단계: sitemap.xml 자체가 문제인 경우

sitemap.xml의 URL 항목이 50,000개를 넘으면 여러 파일로 분할되어야 하고, 각 파일이 50MB 미만이어야 한다. 그 조건을 충족하더라도 lastmod 날짜가 수년 전 그대로이면 구글bot은 이 sitemap을 사실상 무시한다. sitemap.xml의 lastmod 값이 수년 전에 업데이트된 채 방치되어 있다면, 구글bot은 이를 사실상 무시한다.

robots.txt와 상충하는 URL이 sitemap에 포함되어 있으면 문제는 더 심각해진다. 구글bot의 크롤링 예산이 이 중복된 처리에 흡수된다. 직접 만들어서 쓰든, sitemap 생성기를 쓰든, 일관성을 유지하는 게 이 단계의 핵심이다.

4단계: 서버 응답이 병목인 경우

구글bot의 평균 응답 시간 대기 임계값은 대략 2~3초다. GZIP 압축이 안 되어 있거나, 헤더에 불필요한 쿠키가 계속 쌓이거나, 데이터베이스 쿼리가 페이지 로드마다 추가 실행되면 크롤링 속도가 떨어진다. 서버 측에서 GZIP 압축 활성화, 불필요한 헤더 제거, 페이지별 중복 쿼리 제거가 필요하다. 사소한 비효율이 총량으로 쌓이면 상당한 예산 낭비로 이어진다.

5단계: 콘텐츠 품질이 문제인 경우

로우-퀄리티 콘텐츠 디렉티브가 적용되면 구글bot은 얇은 페이지의 크롤링을 대폭 줄인다. 카테고리 페이지의 본문이 200자 미만이거나, 제품 설명이 템플릿 문구의 반복이면 해당 페이지는 구글bot이 와서 빨리 떠나는 구조다.

이 경우 페이지 합치기 또는 파라미터 핸들링이 답이다. 동일 제품의 색상/사이즈 변형을 개별 URL로 생성하는 대신, JavaScript 필터링으로 처리하거나 canonical 태그로 하나의 대표 URL로 집중시켜라.

단기 vs 장기: 결과를 구분해야 산다

robots.txt 수정이나 sitemap 재생성은 3~7일 내에 색인 수 변화가 관찰된다. 빠르게 움직여야 한다. 도메인 권한 구축은 수개월이 걸린다.

결과적으로 네 사이트가 1년차 도메인에 백링크 10개 미만, 페이지 수 800개 중 400개 이상이 얇은 콘텐츠라면, 이 상태에서 크롤링 예산을 최적화하는 건 의미가 희박하다. 기초 권한부터 쌓아야 한다. 구조부터 새로 짜야 한다면, PBN 빌더 자동 백링크 프로그램 분양 같은 도구로 기반부터 다시 잡는 게 시간 대비 효율적이다. 어차피 제자리걸음할 시간이 있으면, 차라리 뒤로 물러서서 다시 시작해라.
