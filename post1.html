크롤 버짓 건강검진: 내 사이트는 몇 점?

구글 색인 요청 후 페이지를 찾지 못하는 문제를 해결하기 위해 발견, 가져오기, 정본화, 색인, 실적의 5단계 URL 관측표를 기준으로 기술적 경로 오류와 구조적 문제를 철저하게 진단하는 구체적인 순서를 설명합니다.

어차피 안 될 사이트는 뭘 해도 안 되겠지만, 일단 돈 값을 하기 위해 씁니다

오늘도 검색 콘솔의 색인 생성 요청 버튼을 마우스가 부서져라 누르고 계셨습니까? 안타깝지만 그런 간절한 염원 따위는 구글봇에게 아무런 감흥을 주지 못합니다. 당신이 백날 요청을 넣어봤자 페이지가 검색에 걸리지 않는 데에는 다 기계적이고 차가운 이유가 있습니다. 이 가이드는 여러분에게 헛된 희망을 심어주려는 글이 아닙니다. 먹고살기 위해 작성하는 철저한 생계형 명세서에 가까우니, 귀찮더라도 모니터를 똑바로 보고 당신의 사이트가 왜 구글의 외면을 받고 있는지 스스로 추적해 보시기 바랍니다.

참고로 시작하기 전에 미리 김을 빼두자면, 무슨 MBTI 검사처럼 '내 사이트 건강 점수: 78점' 같은 편리한 종합 점수표 따위는 이 세상에 존재하지 않습니다. 건강검진이라는 말은 그저 보기 좋은 비유일 뿐이며, 구글이 비공개로 관리하는 절대적인 채점표 같은 것도 없습니다. 우리가 할 수 있는 일은 오직 각 URL의 상태를 아주 지독하고 꼼꼼하게 관측하여 단계별로 쪼개서 분석하는 것뿐입니다.

진짜 문제를 찾아내는 URL별 5단계 관측표

남들이 정리해 놓은 얄팍한 요약글이나 보면서 '요약하자면 열심히 글을 쓰라는 거군요' 같은 영혼 없는 소리는 그만두십시오. 진짜로 오류를 잡아내고 싶다면, 아래의 표를 엑셀이나 메모장에 그대로 복사해 넣은 뒤 의심스러운 URL을 하나씩 대입해 가며 추적해야 합니다. 구글봇의 시선은 절대 단계를 건너뛰지 않습니다.

1단계: 발견 (Discovery) — 존재조차 모르는 페이지의 슬픔

구글봇이 당신의 페이지를 발견이라도 하려면 기술적 연결 고리가 있어야 합니다. 가장 흔히 하는 실수가 본문 속에 요란한 자바스크립트나 알 수 없는 클릭 이벤트로 링크를 숨겨두는 짓입니다. 구글봇은 웹 표준을 지키는 단순하고 명확한 구조를 좋아합니다. 실제 a 요소와 href 속성이 온전하게 구현된 링크가 없다면, 그리고 그 링크의 앵커 텍스트가 목적지 페이지를 제대로 설명하지 않는다면 크롤러는 해당 경로를 타고 들어가지 않습니다. 사이트맵에 쑤셔 넣었다고 끝이 아닙니다. 내부 링크 구조가 엉망이면 구글은 그 페이지를 구석진 독방에 갇힌 쓸모없는 문서로 판단할 뿐입니다.

2단계: 가져오기 (Crawl) — 대규모 사이트의 핑계 뒤에 숨지 마십시오

검색 콘솔에서 '발견됨 - 현재 색인이 생성되지 않음' 문구를 보면 십중팔구 '아, 크롤 버짓(Crawl Budget)이 부족해서 구글이 내 사이트를 덜 긁어가는구나'라며 자위하곤 합니다. 냉정하게 말해서 당신의 사이트가 수십만 개의 페이지를 거느린 대형 커뮤니티나 언론사가 아니라면 크롤 자원 결핍은 남 일입니다. 중소형 사이트에서 발견됨-미색인 비중이 크다고 해서 대기업 수준의 크롤 버짓 부족으로 넘겨짚을 수는 없지만, 기술적 경로 차단이나 서버 오류, 콘텐츠의 검색 가치 부족 등 복합적인 요인이 없는지 차분히 점검하는 게 맞습니다. 기술적 관문을 통과하지도 못했는데 버짓 타령을 하는 건 참으로 보기 민망한 꼴입니다.

3단계: 정본화 (Canonicalization) — 대표 주소는 당신이 구걸하는 게 아닙니다

정본 선언(Canonical)은 구글에 바치는 일종의 '제안'이나 '선택 신호'일 뿐입니다. 당신이 특정 URL에 정본 태그를 달아두었다고 해서 구글이 무조건 그것을 대표 주소로 삼아줄 것이라는 기대는 접는 게 좋습니다. 내부 링크가 가리키는 주소와 사이트맵에 기재된 주소, 그리고 실제 canonical이 가리키는 주소가 제각각 놀아나면 구글은 당신의 제안을 가볍게 씹고 자기 마음대로 엉뚱한 페이지를 대표로 선정합니다. 그리고 제발, 중복 페이지를 정리한답시고 검색 콘솔의 'URL 제거 도구'를 함부로 남용하지 마십시오. 그건 영구적인 정본 정리 수단이 아니라 급하게 검색 결과에서 임시로 주소를 가려야 할 때 쓰는 응급처치 도구에 불과합니다.

4단계: 색인 (Indexing) — AI 시대에도 뼈대는 변하지 않는다

요즘은 인공지능이 알아서 검색 결과를 요약해 주니 기존의 클래식한 색인 방식 따위는 몰라도 된다고 주장하는 무식한 이들이 보입니다. 기가 찰 노릇입니다. 구글의 AI 검색 최적화 기술 역시 결국은 기존 검색 엔진이 수집해 놓은 독립적이고 가치 있는 색인 구조를 기반으로 작동합니다. 페이지 개수만 무작정 늘린다고 해서, 혹은 구글 가이드라인을 기계적으로 조금 맞췄다고 해서 자동으로 검색 노출이 보장되지는 않는다는 뜻입니다. 독자가 진짜로 궁금해하는 구체적인 질문에 독립적인 답변을 제공하고 있는지, 이 문서를 작성한 출처나 배경이 투명한지 점검하십시오. 허울뿐인 형식 맞추기는 구글봇에게 아무런 감동을 주지 못합니다.

5단계: 실적 (Performance) — 데이터의 냉혹한 현실

색인까지 겨우 완료되었다 해도 검색 결과 화면에 구조화 데이터를 적용했다고 무조건 노출이 보장되는 법은 없습니다. 많은 대행사들이 구조화 데이터만 심으면 대단한 후기 별점이나 FAQ가 검색 결과에 웅장하게 깔릴 것처럼 광고하지만, 실제 사용자가 보지도 못할 허위 리뷰 정보를 숨겨두거나 본문과 무관한 마크업을 끼워 넣으면 구글은 가차 없이 해당 기능을 제한합니다. 게다가 E-E-A-T라는 것은 무슨 백신 주사 맞듯이 한 번에 획득할 수 있는 정량적 점수가 아닙니다. 각 문서가 독자의 필요에 얼마나 부합하는지를 다각도로 판단하는 무형의 기준일 뿐입니다. 지름길은 없습니다. 어차피 이렇게 말해줘도 대다수는 내일 아침 다시 색인 요청 버튼만 하염없이 연타하고 있겠지만 말입니다.

이 문서에서 묻는 질문

색인 생성을 요청했는데도 페이지가 검색에 잡히지 않을 때 가장 먼저 확인해야 할 관측 항목은 무엇인가요?

단순히 색인 요청 버튼을 반복해서 누르지 말고, 발견(Discovery) 단계에서 크롤러가 해석할 수 있는 올바른 a 요소와 href 속성을 갖춘 내부 링크가 존재하는지 확인한 후, 가져오기(Crawl) 단계에서 서버가 200 정상 응답을 주는지와 '발견됨-현재 색인이 생성되지 않음' 상태가 기술적 경로 오류나 사이트 품질 부족 때문인지 URL별 관측표를 작성하여 단계적으로 진단해야 합니다.
