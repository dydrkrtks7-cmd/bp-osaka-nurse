구글봇 자원 배분 최적화: 정밀 관찰과 제어

소규모 사이트의 크롤링 누수를 진단하기 위해 서버 사양을 의심하기 전 404/5xx 에러, robots.txt, 정본 URL 선언, 실제 a 태그 링크 구현 여부를 조건별로 점검하는 실무적인 가이드라인을 제공합니다.

구글봇이 네 사이트를 거들떠보지도 않는 진짜 이유

어차피 내가 이렇게 시간 들여서 자가 진단법을 길게 설명해 봤자, 대부분은 대충 훑어보고 가비아나 카페24 기본 호스팅 탓만 하다가 끝낼 게 뻔하다. 솔직히 말해서 하루 방문자가 백 명도 안 되는 자그마한 사이트에서 '크롤 버짓(Crawl Budget)'이 모자라네 마네 하면서 호들갑을 떠는 것만큼 우스운 일도 없다. 구글의 공식적인 크롤링 가이드를 보면 알겠지만, 발견됨-미색인 비중이 비정상적으로 크다고 해서 무조건 대기업 사이트 같은 크롤링 자원 결핍 상태라고 단정해서는 안 된다. 사이트 구조에 빈틈이 있는지 확인해볼 일이다. 다만 그 검사만으로 Google의 선택 이유가 전부 설명되지는 않는다.

열심히 글을 써서 올리는데도 검색 엔진에 반영이 안 된다고 징징대기 전에, 네가 싼 똥(에러)부터 치웠는지 확인해라. 봇은 자비롭지 않다. 쓸데없는 곳에 봇의 시간을 낭비하게 만들면, 정작 중요한 새 페이지를 발견하고 확인하는 일이 늦어질 수 있다. 돈 한 푼 안 들이고 지금 당장 네 손으로 점검할 수 있는 것들이 널려 있는데, 왜 엄한 웹서버 성능 업그레이드에 돈을 쓰려고 하는가.

서버 탓하기 전에 털어봐야 할 조건별 점검 순서

지갑 사정도 뻔할 텐데 엄한 데 돈 쓰지 말고, 일단 내 말을 믿고 아래 순서대로 사이트 밑바닥부터 뜯어봐라. 어차피 안 될 놈은 안 되겠지만, 최소한 이 순서대로만 점검해도 구글봇이 네 사이트에서 헤매다 튕겨 나가는 불상사는 막을 수 있다.

1단계: 404 에러와 서버 오류(5xx) 청소하기

봇이 주소를 따라 들어갔는데 404(페이지 없음)나 5xx(서버 내부 오류)가 무더기로 뜨면, 봇은 이 사이트가 제대로 관리되지 않는 유령선이라고 판단한다. 당연히 방문 빈도를 줄인다. 서버 로그를 열어보든가 구글 서치 콘솔의 색인 생성 범위 보고서를 열어서 빨간색으로 뜨는 에러 경로를 전부 확인해라. 이미 없어진 페이지라면 robots.txt로 막거나 올바른 페이지로 리디렉션을 시켜야지, 방치해 두는 건 나 크롤링 거부하겠다고 광고하는 꼴이다.

2단계: robots.txt와 실제 접근 허용 영역 대조

가끔 보면 어설프게 배운 지식으로 robots.txt 파일에 Disallow 설정을 남발해서 정작 봇이 긁어가야 할 꿀 같은 콘텐츠 페이지까지 꽁꽁 막아두는 멍청한 짓을 한다. 반대로 회원가입 페이지나 내부 검색 결과 페이지처럼 백해무익한 더미 주소들을 활짝 열어두어 봇이 쓰레기 데이터를 수집하느라 시간을 허비하게 만든다. 지금 당장 메모장을 켜고 네 사이트의 robots.txt에 명시된 규칙이 실제 페이지 경로와 모순되지 않는지 대조해라.

3단계: 엉망진창인 중복 주소(Canonical)와 사이트맵 싱크 맞추기

이게 진짜 설명해 줘도 매번 틀리는 단골 메뉴다. 하나의 페이지를 가리키는 주소가 여러 개 있을 때(예컨대 파라미터가 붙은 주소 등) 구글에 어떤 게 '정원본'인지를 알려주는 정본(Canonical) 선언은 어디까지나 구글에 주는 '선택 신호'일 뿐이다. 구글이 이걸 무시하고 엉뚱한 주소를 긁어가는 이유는 네가 상충되는 신호를 사방에 뿌려놨기 때문이다. XML 사이트맵에 적어둔 주소, 본문 내부 링크에 쓴 주소, 그리고 실제 canonical 태그로 선언한 정본 주소가 삼위일체로 똑같아야 봇이 혼란을 겪지 않는다. 이 세 개가 서로 다른 주소를 가리키고 있으면 Google은 선언한 주소와 다른 신호를 함께 대조하여 별도의 대표 URL을 선택할 수 있다. 덧붙여 말하는데, URL 제거 도구는 일시적으로 검색 결과에서 감추는 임시방편일 뿐이지 정본 정리 수단이 아니니까 제발 헛수고하지 마라.

4단계: 겉멋만 든 자바스크립트 가짜 링크 걷어내기

요즘 트렌디하게 만든답시고 자바스크립트 클릭 이벤트로 화면을 전환하고, 정작 HTML 코드에는 <a href="#"> 이딴 식으로 적어두는 개발자들이 천지다. 구글봇은 사람처럼 화면을 클릭하며 돌아다니지 않는다. 구글봇은 실제 href 속성에 구체적이고 유효한 URL 경로가 적혀 있는 a 요소만을 타고 이동한다. 링크에 들어가는 앵커 텍스트도 '더 보기'나 '여기를 클릭' 같은 아무 의미 없는 단어 대신, 도착할 페이지의 핵심 정보를 담은 설명으로 채워라. 귀찮다고 안 하면 네 사이트는 영원히 고립된 섬으로 남을 것이다.

AI 검색 시대라고 해서 꼼수가 통할 것 같은가

인공지능이니 생성형 검색이니 세상이 떠들썩하니까, 이제는 기술적인 검색 최적화(SEO)가 필요 없고 글만 잘 쓰면 장땡이라고 생각하는 부류가 있더라. 착각하지 마라. 구글의 AI 검색 최적화 가이드를 정독해 봐도, 그 기저에 깔린 건 결국 동일한 기술적 크롤링 경로와 읽기 좋은 웹 구조다. 사이트에 페이지가 수만 장 쌓여 있다고 해서, 혹은 구글이 권장하는 조건 몇 개 억지로 채웠다고 해서 검색 노출이 백 퍼센트 보장되는 일 따위는 존재하지 않는다.

흔히들 오해하는 구조화 데이터(Schema Markup)도 그렇다. 화면에는 보이지도 않는 가짜 이용자 후기나 묻고 답하기(FAQ)를 마크업에 쑤셔 넣는 꼼수를 부려봤자 구글은 바보가 아니다. 구조화 데이터는 페이지 내에 실제로 떡하니 존재하는 콘텐츠를 검색 엔진이 기계적으로 더 잘 이해하도록 돕는 보조 도구일 뿐이지, 없는 사실을 지어내서 점수를 따는 보증 카드가 아니다. 기본 독자의 필요를 채우는 독립적이고 쓸모 있는 답변을 쓰고, 출처와 작성 배경을 떳떳하게 밝히는 투명한 글쓰기가 선행되지 않으면 아무리 마크업을 화려하게 발라도 소용없다.

크롤링 효율 극대화를 위한 현장 점검표

다들 읽고 까먹을 게 뻔하니, 이거라도 복사해서 매주 월요일마다 네 눈으로 직접 체크해 봐라. 최소한 돈 날리는 일은 줄어들 것이다.

귀찮아도 이 짓을 해야 봇이 네 사이트에 정을 붙이고 자주 찾아온다. 어차피 안 할 사람은 끝까지 안 하겠지만, 네 사이트가 구글에서 영영 사라지는 꼴을 보기 싫다면 당장 오늘 저녁에 맥주 한 잔 마시면서 코드 한 줄이라도 들여다보는 성의를 보여라. 세상에 공짜 노출 같은 건 없다.

이 문서에서 묻는 질문

작은 블로그인데도 구글봇이 잘 안 오는 이유가 크롤 버짓이 부족해서인가요?

아닙니다. 소규모 사이트의 경우 물리적인 크롤링 자원(Crawl Budget) 자체가 부족한 경우는 드뭅니다. 소규모 사이트의 미색인을 기술적 결함 하나로만 단정할 수는 없습니다. 다만 서버 탓을 하기 전에 404 에러 누적, robots.txt 차단 실수, 사이트맵과 정본(canonical) 주소의 불일치 같은 기초적인 탐색 경로 오류가 없는지 우선 확인해보는 것이 순서입니다.

중복 URL을 정리하기 위해 서치 콘솔의 URL 제거 도구를 쓰면 되나요?

절대 안 됩니다. URL 제거 도구는 일시적으로 검색 결과에서 긴급하게 페이지를 숨기는 임시 도구일 뿐입니다. 중복 주소를 해결하려면 HTML 소스 내의 canonical(정본) 태그를 통일하고, XML 사이트맵 및 실제 내부 링크(href) 주소를 삼위일체로 일치시켜야 합니다.
